Project create + GitHub import — Final report

Repo: cohort · Branch: feat/project-create-import · Commit: d0cb715 · 2026-09-15 · Design: design.html · Plan: plan.html

1. Outcome

Cohort's New Project flow now supports two sources. Create local (point at an existing checked-out repo) already existed and is preserved and regression-guarded. Import from URL is new: the user pastes a git/GitHub URL and picks a parent folder, the server clones the repo into <parent>/<repo-name>, then reuses the existing create-with-Team-Lead path against the clone. Failures (invalid URL, private/auth-required, unreachable, target exists) return a clear message with no hang and no partial project. Work is committed on feat/project-create-import; PR to be opened (see §10). Headline caveat: the design was taken as-proposed under an unattended one-shot invocation (no human sign-off), and three UX/policy defaults are recorded as unconfirmed assumptions (§8).

2. Delivered

  • Discriminated-union createProjectSchema (local | import) with z.preprocess back-compat so bodies without source still create a local project.
  • isGitUrl validation (https/http/ssh/git/scp/file forms) — server refine + client-side inline check.
  • Standalone cloneRepoToDir (src/server/clone.ts) — non-throwing, GIT_TERMINAL_PROMPT=0 fail-fast, partial-dir cleanup; deliberately kept off the worktree-scoped GitService.
  • deriveRepoName + importProjectFromUrl service: name-normalized, target-exists guard, clone-failure → ProjectImportError → HTTP 400, no store write on failure.
  • POST /api/projects branches on source; response shape {project, agents} unchanged.
  • New Project modal: Local / Import tabs, URL + parent-folder inputs (reuses the folder picker).
  • Tests: 11 unit, 7 integration (real git clone of a real fixture), 3 e2e (Playwright).

Not delivered (out of scope by design)

  • Stored credentials / tokens, SSH-key management, host allow-listing — private repos rely on the ambient git credential helper.
  • Streamed clone progress UI; editing a project's remote after creation; non-git sources.

8. Assumptions still unconfirmed

  • Design taken as-proposed without human sign-off (unattended one-shot invocation).
  • Q1: clone lands at <parent>/<repo-name>, target subdir must not already exist.
  • Q2: public HTTPS + ambient git credentials for private; GIT_TERMINAL_PROMPT=0; no token stored.
  • Q3: URL validation is UX-level (accepts https/ssh/scp/git/file), not a security boundary (local single-user app). Note: file:// was added beyond the original https/ssh/scp scope to enable offline real-clone tests — it is a harmless superset.

9. Follow-ups

  • Streamed clone progress + cancel for large repos.
  • Optional explicit token field for private repos that don't use a credential helper.
  • Address the orchestration-suite parallel-load timeouts (raise timeouts or cap worker concurrency in vitest config).
