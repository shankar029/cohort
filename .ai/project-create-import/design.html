Design — Project create + GitHub import

Cohort — Fastify server + React web, TypeScript, better-sqlite3. Grounded in research.md (commit 8776239), clarifications.md, traceability.md.

1. Problem & scope

  • AC1 — Create a project from an existing local repo directory. Already implemented; this design only notes how it is regression-guarded.
  • AC2 — Import a project by GitHub URL: clone the repo locally, then create a project from the clone.
  • AC2.1 — Reject invalid/malformed URLs with a clear, user-visible error.
  • AC2.2 — Clone failure (bad repo, auth required, network) surfaces a clear error, no hang, no partial project.
  • AC2.3 — New Project modal lets the user choose import-by-URL vs create-local.

Out of scope: storing tokens/credentials; SSH-key management; host allow-listing; background/streamed clone progress; editing a project's remote after creation; non-git sources.

A1 (Q1): a URL clone lands at <parentDir>/<repoName> where the user picks a parent directory (reusing the existing folder picker) and repoName is derived from the URL; the target subdir must not already exist.

A2 (Q2): v1 supports public HTTPS clone and relies on the ambient git credential helper for private repos; GIT_TERMINAL_PROMPT=0 forces fail-fast (no hang). No token is stored.

A3 (Q3): accept well-formed https://…(.git) and git@host:… / ssh:// forms; trim; reject empty/malformed. Validation is for UX correctness, not a security boundary (local single-user app).

As-is → to-be (changed existing symbols)

  • createProjectSchema — as-is a flat z.object({name, repoDir, defaultModel?, createDir?}) (research §2, api.ts:9-16). To-be a discriminated union on source: 'local' keeps today's fields; 'import' adds repoUrl + parentDir. source defaults to 'local' so existing callers stay valid (additive/back-compat).
  • GitService — as-is worktree-scoped git CLI wrapper; class doc: "All operations are scoped to managed clones under worktreeRoot" (research §4, git.ts:41-93). To-be unchanged. URL clone lives in a new standalone src/server/clone.ts (its own execFile wrapper that sets GIT_TERMINAL_PROMPT=0), so GitService's invariant is preserved and no GitService instance is needed in buildApp (which does not receive one — app.ts:24-31, 109-110, index.ts:49-56).
  • POST /api/projects — as-is always calls validateRepoDir → createProjectWithLead (research §2, app.ts:159-167). To-be branches: source==='import' → importProjectFromUrl; else the existing path.
  • web/api.ts createProject / state.createProject / CreateProjectModal — as-is local-only input {name, repoDir, defaultModel?, createDir?} (research §2, api.ts:60-64, state.tsx:295-300, ProjectsPage.tsx:222-266). To-be input type widens to the union; modal adds an import tab.

3. Key interactions

Happy path (top): clone succeeds, then the existing lead-creation path runs against the cloned dir. Failure path (bottom): cloneRepo returns ok:false; service throws HttpError(400, stderr-summary); nothing is written to the store, so no partial project. GIT_TERMINAL_PROMPT=0 guarantees the clone fails fast instead of hanging on a credential prompt (AC2.2).

4. Data & contracts

Discriminated union in src/shared/api.ts, wrapped so a body that omits source still parses as 'local' (back-compat for existing callers — fixes review #4):

const localSchema = z.object({
  source: z.literal('local'),
  name: z.string().trim().min(1).max(80),
  repoDir: z.string().trim().min(1),
  defaultModel: z.string().trim().min(1).optional(),
  createDir: z.boolean().optional(),
});
const importSchema = z.object({
  source: z.literal('import'),
  name: z.string().trim().max(80).optional(),   // default: derived repo name
  repoUrl: z.string().trim().min(1).refine(isGitUrl, 'Enter a valid git URL'),
  parentDir: z.string().trim().min(1),
  defaultModel: z.string().trim().min(1).optional(),
});
// z.preprocess injects source:'local' when missing, BEFORE the union reads the
// discriminator — so old bodies { name, repoDir } keep working (verified by a test).
export const createProjectSchema = z.preprocess(
  (v) => (v && typeof v === 'object' && !('source' in v) ? { ...v, source: 'local' } : v),
  z.discriminatedUnion('source', [localSchema, importSchema]),
);
export type CreateProjectInput = z.infer<typeof createProjectSchema>;
export type ImportProjectInput = z.infer<typeof importSchema>;

Name normalization (fixes review #3): importProjectFromUrl resolves name = input.name?.trim() || deriveRepoName(input.repoUrl) (never undefined), then builds a local-shaped input { name, repoDir: clonedPath, defaultModel } and calls createProjectWithLead — so tsc proves name is present and the reused create path is unchanged.

Route order (fixes review #5): the handler branches on input.source as the first statement after parse; the import branch never reads input.repoDir / calls validateRepoDir (that stays in the else).

  • Request (POST /api/projects): either variant above. isGitUrl accepts https://host/x/y(.git), git@host:x/y(.git), ssh://…; trims; rejects empty/malformed (AC2.1).
  • Response (unchanged shape): 201 { project: Project, agents: Agent[] } — additive, so state.createProject (state.tsx:476-480) keeps working.
  • Errors: ZodError→400 {error:'Validation failed', details}; HttpError→its status {error}; the web request<T> surfaces body.error to the modal (research §4).
  • Project.repoDir stays a local path (domain.ts:58-62) = the cloned <parentDir>/<repoName>; no schema change to the domain type.

5. Decisions & trade-offs

DecisionRejected alternativeWhy
Single POST /api/projects with a source branch Separate POST /api/projects/import route Same response, same downstream (lead creation); one entry point avoids duplicating wiring and keeps web client symmetric. Discriminated union already encodes the branch.
Standalone cloneRepoToDir in a new src/server/clone.ts Add a cloneRepo method to GitService; or thread a GitService into buildApp GitService is worktree-scoped by contract (git.ts:41-49) and buildApp never receives an instance (index.ts:49-56). A URL clone writes to a user-chosen dir outside worktreeRoot, so it belongs in its own small module — the route/service imports the function directly with no wiring change. This resolves both the SRP violation and the feasibility blocker from Gate 2b.
Derive repo name from URL → clone into <parent>/<name> User types the exact target dir (like local repoDir) Matches native git clone <url> behavior and the existing "pick a folder" UX; avoids clobbering an existing dir; less typing/error for the user. Guard: target subdir must not already exist.

6. Risks, edge cases & failure modes

CaseHandling
Target dir already existsPre-check in importProjectFromUrl before clone: if <parent>/<name> exists → HttpError(400, 'Target folder already exists: …'); never clone over it.
Clone requires auth (private repo, no creds)GIT_TERMINAL_PROMPT=0 makes git fail fast; cloneRepo returns ok:false; mapped to a clear HttpError. No hang (AC2.2).
Invalid / malformed URLRejected at zod boundary via isGitUrl refine → 400 before any git call (AC2.1).
Partial clone on failureService treats ok:false as fatal and does not call createProjectWithLead; optionally best-effort remove a partial dir git left behind, then throw. No project row is written (AC2.2).
git not on PATHexecFile('git', …) errors → ok:false, stderr surfaced as HttpError with an actionable message. Not currently a documented prereq for import (docs/DEVELOPMENT.md:9-14).
Long / large cloneSynchronous HTTP request; acceptable for v1 (no progress stream). Note UX/timeout budget for the integration test (vitest.config.ts testTimeout 20000); use a tiny fixture repo. Streaming progress is out of scope.
Empty/odd repo name derivation (e.g. URL ends in /)deriveRepoName sanitizes and falls back; if empty → validation error (AC2.1). Exact fallback string is an implementation choice.
