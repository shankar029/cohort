1. Problem & approach

The design-first-orchestration feature (PRs #1/#2/#4) is proven by unit + integration tests using the fake adapter — but the fake writes files regardless of persona text, so AC4 ("greenfield Frontend decides and produces code instead of stalling") and AC5 ("Architect states a stack; design persisted before builders act") are only VERIFIED-WITH-LIMITATIONS. This work proves them live.

FACT (this session): the real Copilot adapter connects here (CopilotClient().start() ok, listModels() → auto). FACT: an isolated live harness already exists — evals/harness.mjs + evals/run.mjs — that boots the real server against a greenfield repo, drives it over HTTP/WS, and scores deliverables. Approach: extend that harness with the two signals it lacks (a per-stream deliverable attribution and a read of the persisted design) and add one focused scenario. No new tool, no production code, no CI test (a live LLM run is non-deterministic and must stay opt-in).

5. Two-mode validation

--fake proves the scoring plumbing deterministically (design persisted by the fake's structured-breakdown turn, markers enrich tasks, fake writes files → frontendProducedCode true) — this is the Gate-4 self-test, no auth, seconds. The real run proves the behavior (Gate 5). The split is deliberate: the fake can't fake a real stack decision, so only the live run closes AC4/AC5.

6. Failure modes & edge cases

  • Early-stop needs rich reads (review F1). monitorUntil is extended to pass this (the harness) as a 2nd arg to until(snap, h) — backward-compatible, since every existing scenario's until is unary and ignores it. The design-first until does the cheap snapshot check first (epic done, or a frontend-stream task terminal) and only then reads the design/clones, so the 5s poll stays light.
  • Live run times out mid-epic. the report is captured with whatever was proven and per-AC verdicts reflect that honestly (never claim an unobserved pass).
  • Frontend clone GC'd after merge → primary attribution uses the task branch ref; only if that is also gone does the guarded, sole-code-author fallback apply (review F3).
  • WAL read. better-sqlite3 opened { readonly: true, fileMustExist: true } reads a live WAL db safely; wrapped in try/catch → empty on any error, so scoring degrades, never crashes.
  • Frontend stalls on a question (the very bug under test). the harness does not auto-answer — a stall must surface, not be hidden. userQuestionsRaised is recorded; if the frontend stalls and never produces code, AC4 fails honestly and the scenario ends at its (modest) timeout (review F6, accepted).
  • Auth failure. detectAuthIssue() surfaces it from the server log; AC-H fails loudly rather than a false green.
  • Model only auto. fine — agents default to it.
