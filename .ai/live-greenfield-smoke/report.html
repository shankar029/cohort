1. Outcome (headline)

Built and ran a repeatable, opt-in live smoke (extending evals/) that boots Cohort with the real Copilot adapter against a greenfield repo and scores the design-first behaviors. The harness works (AC-H VERIFIED) — and it did its job: it proved, with evidence, that AC4 and AC5 do NOT hold live. On a greenfield repo the Architect's design turn returned empty text, so no stack/design was persisted, and the Frontend re-exhibited the original no-code stall and escalated to the user. This is a product defect in the previously-shipped design-first feature (PR #4), surfaced by this task — not a defect in the harness.

This is a successful verification run with a negative result. The deliverable was the live-proof capability plus an honest verdict; a green checkmark on AC4/AC5 was not achievable because the feature itself is not yet correct live.

4. Root cause (the finding)

The design-first flow collapses when the real Architect turn returns empty. designThenEnrich guards on if (!text) return (orchestrator.ts ~1281) — correct for never-stranding, but it means an empty/tool-only architect turn silently persists no design (epic_designs stayed empty in both runs). With no stack/spec to anchor to, the greenfield Frontend stalls ("no deliverable after 2 attempts"); the shipped Lead-first escalation re-drives it, and it still escalates to the user. Raising ATEAM_DESIGN_TIMEOUT_MS to 4 min (run 2) did not help — the turn was empty, not slow. Secondary: builders are dispatched before the design settles and only wait ATEAM_DESIGN_WAIT_MS (45s), and the 45s timeouts are fake-tuned.
